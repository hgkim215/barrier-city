# 키오스크 카테고리 장벽 및 화면 재설계

날짜: 2026-08-17  
대상 브랜치: `codex/kiosk-screen-ui`  
대상: visionOS `Barrier City` Indoor 키오스크

## 1. 목적

실제 키오스크 화면에서 SwiftUI 콘텐츠가 상하좌우 반전되어 보이는 문제를 바로잡고, 첨부 레퍼런스의 밝고 선명한 카페 메뉴 구조로 UI를 개선한다.

이번 장면의 핵심은 주문 성공이 아니라 접근성 장벽의 체험이다. 휠체어 이용자는 레인보우 스무디를 찾기 위해 화면 상단의 `기타` 카테고리를 선택하려 하지만, 높은 위치 때문에 선택하지 못한다. 키오스크는 실패 이유를 명확히 보여 주고 사용자가 `직원에게 직접 주문하기`를 선택하면 다음 미션으로 전환한다.

## 2. 관찰된 원인과 제약

- 실제 실행 화면에서 UI 전체가 정확히 180도 회전해 보인다. 글자뿐 아니라 상단·하단과 좌우 배치가 모두 뒤집혀 있으므로 텍스트 렌더링 문제가 아니라 attachment의 로컬 평면 방향 문제다.
- `KioskScreenPresenter`는 `Screen/Plane`의 자식으로 attachment를 배치하면서 로컬 회전을 identity로 둔다.
- `Screen.usdz`의 `Plane`에는 자체 회전이 적용되어 있어 SwiftUI attachment의 위·오른쪽 축과 실제 디스플레이의 위·오른쪽 축이 반대다.
- 평면 로컬 Z축을 기준으로 180도 회전하면 X·Y축만 함께 뒤집고 화면 법선은 유지할 수 있다.
- 첨부 이미지는 완성된 UI의 시각·정보 구조 참고 자료다. 이미지 속 외부 상품 사진을 그대로 앱 자산으로 복제하지 않는다.
- 기존 Mission 2 → 키오스크 실패 → Mission 3 → 직원 NPC 접근 흐름은 유지한다.

## 3. 검토한 상호작용 방식

### 방식 A — `기타` 탭 자체에서 장벽 발생 (채택)

- 일반 카테고리는 정상적으로 전환된다.
- Mission 2에서 `기타`를 시도하면 선택 상태와 메뉴 목록은 바뀌지 않고 접근 불가 경고가 열린다.
- 사용자가 경고의 `직원에게 직접 주문하기`를 누를 때 Mission 3로 전환한다.

장점은 "높은 카테고리에 닿지 못해 원하는 메뉴를 찾을 수 없다"는 사용자 요청과 접근성 메시지가 가장 정확하게 일치한다는 점이다. 시선+핀치와 손 뻗기 모두 같은 결과를 내므로 Simulator와 실기기에서 이야기가 달라지지 않는다.

### 방식 B — `기타` 목록 진입 후 레인보우 스무디에서 장벽 발생

원하는 메뉴를 화면에 직접 보여 줄 수 있지만, 문제의 원인이 카테고리 높이라는 설정이 약해진다. 이번 구현에서는 채택하지 않는다.

### 방식 C — 손 뻗기만 실패하고 시선+핀치는 정상 전환

물리적 거리 표현은 강하지만 visionOS 기본 선택 방식으로 장벽을 우회할 수 있고 Simulator 데모 흐름도 달라진다. 이번 구현에서는 채택하지 않는다.

## 4. 확정된 사용자 흐름

```text
Mission 2 + 키오스크 근접
  → 베스트 카테고리 화면, 입력 활성
일반 카테고리 선택
  → 선택 탭과 메뉴 목록 전환
기타 선택 시도
  → 기타는 미선택 유지
  → "높아서 선택할 수 없습니다" 경고 표시
다시 시도/경고 닫기
  → Mission 2 유지, 키오스크 사용 재시도 가능
직원에게 직접 주문하기
  → 경고 닫기 + 키오스크 입력 잠금
  → kioskFailed 1회 발행
  → Mission 3로 갱신, 직원 NPC 주문 흐름 안내
```

Mission 갱신은 경고가 나타난 순간이 아니라 사용자가 대안을 선택한 순간에 실행한다. 경고를 읽고 `닫기`를 선택할 수 있게 해 사용자 통제권을 유지한다.

## 5. 화면 디자인

### 5.1 전체 구조

- 기존 540×960, 9:16 캔버스를 유지한다.
- 배경은 따뜻한 고채도 노랑, 주요 글자와 테두리는 검정, 가격과 경고 강조는 빨강을 사용한다.
- 최상단에는 홈 아이콘과 `BARRIER CAFE` 타이틀을 둔다.
- 그 아래 카테고리를 4열 × 2행으로 배치한다.
- 중앙은 3열 메뉴 카드 그리드다.
- 하단에는 선택 상품 요약과 검은색 주문 버튼을 배치한다. 실제 결제 기능은 제공하지 않는다.
- 키오스크 접근성 실패 메시지는 화면 하단의 작은 토스트가 아니라 중앙 경고 카드로 표시해 앉은 시야에서도 읽을 수 있게 한다.

### 5.2 카테고리

카테고리는 다음 순서로 고정한다.

```text
베스트 | 커피 | 티 | 에이드
논커피 | 디카페인 | 기타 | 전체
```

- 선택된 탭: 검정 배경 + 흰색 글자
- 선택되지 않은 탭: 노랑 배경 + 검정 테두리·글자
- 일반 탭을 선택하면 180~220ms ease-out으로 선택 상태와 메뉴 콘텐츠를 교체한다.
- `기타`는 겉보기에는 다른 탭과 동일하되 Mission 2에서 선택 시도 시 눌림 피드백 뒤 원래 상태로 복귀하고 경고를 연다.

### 5.3 메뉴 카드

- 흰색 또는 매우 옅은 회색 카드, 큰 음료 심볼/일러스트, 굵은 상품명, 빨간 가격 순서로 구성한다.
- 별도 개별 상품 사진이 없으므로 프로젝트 안에서 재사용 가능한 SwiftUI 도형과 시스템 심볼로 음료 종류를 구분한다.
- 각 카테고리는 최소 6개, 기본 화면은 9개 메뉴를 제공한다.
- `기타` 데이터에는 `레인보우 스무디`를 첫 항목으로 포함해 상태·미리보기·테스트에서 서사가 드러나게 한다. Mission 2 사용자 화면에서는 탭 장벽 때문에 이 목록에 진입하지 못한다.
- 일반 메뉴 카드는 선택 상태를 바꿀 수 있지만 주문 성공이나 결제는 진행하지 않는다.

### 5.4 경고 카드

- 제목: `높아서 선택할 수 없습니다`
- 설명: `앉은 자세에서는 기타 카테고리에 손이 닿지 않습니다. 카페 직원에게 직접 주문해 보세요.`
- 기본 행동: `직원에게 직접 주문하기`
- 보조 행동: `닫기`
- 경고가 열려 있는 동안 뒤쪽 메뉴 입력은 막는다.
- 기본 행동은 Quest 이벤트를 한 번만 발행한다.

## 6. 상태와 책임

### 6.1 `KioskInteractionState`

다음 순수 상태를 소유한다.

- 선택된 카테고리
- 선택된 메뉴 항목
- 장벽 경고 표시 여부
- 세션 입력 잠금 여부

행동은 일반 카테고리 선택, `기타` 접근 시도, 메뉴 선택, 경고 닫기, 직원 도움 선택으로 구분한다. `기타` 접근 시도만 장벽 상태를 만든다. 기존의 "어떤 메뉴를 눌러도 실패" 동작은 제거한다.

### 6.2 `KioskOrderView`

- 카테고리와 메뉴 데이터의 렌더링을 담당한다.
- 비즈니스 상태 전이는 `KioskInteractionState`의 행동을 호출한다.
- Quest 이벤트를 직접 중복 발행하지 않고 `InteractionModel.requestKioskStaffHelp()` 단일 경로를 사용한다.

### 6.3 `KioskReachAttemptDetector`

- 기존 근접·상향 손 뻗기 감지는 유지한다.
- Mission 2의 활성 키오스크에서 감지가 발생하면 `기타` 탭 접근 시도와 동일한 장벽 상태를 만든다.
- 시선+핀치와 손 뻗기 경로가 동시에 들어와도 경고와 Quest 전환은 한 번만 발생한다.

### 6.4 `KioskScreenPresenter`

- attachment를 `Plane` 로컬 Z축 기준 π 라디안 회전해 실제 디스플레이의 위쪽과 SwiftUI의 위쪽을 일치시킨다.
- 회전은 위치, 스케일, 화면 법선 방향을 바꾸지 않는다.
- 회전값은 `KioskScreenTuning`에 모아 순수 테스트로 계약을 고정한다.

## 7. 오류 및 경계 조건

| 상황 | 처리 |
|---|---|
| Mission 2가 아니거나 키오스크 밖 | 카테고리와 메뉴 입력 무시 |
| `기타` 경고를 닫음 | Mission 2 유지, 기존 선택 카테고리 유지 |
| 직원 도움 버튼 연타 | 첫 호출만 수락, Mission 3 전환 1회 |
| 손 뻗기와 탭 동시 입력 | 첫 장벽 전이만 수락 |
| 세션 재진입 | 베스트 선택, 메뉴 미선택, 경고 닫힘, 잠금 해제 |
| `Screen/Plane` 없음 | 기존 월드 고정 폴백과 fail-open 유지 |
| 상품 데이터 누락 | 빈 화면 대신 사용 가능한 메뉴만 안정적으로 표시 |

## 8. 검증

### 8.1 자동 검증

1. 초기 카테고리는 `베스트`다.
2. 일반 카테고리는 선택 상태와 메뉴를 전환한다.
3. `기타` 시도는 선택 카테고리를 유지하고 경고만 연다.
4. 경고 닫기는 Mission 2와 입력 가능 상태를 유지한다.
5. 직원 도움 선택은 입력을 잠그고 Quest 전환 요청을 한 번만 만든다.
6. 일반 메뉴 선택은 장벽 경고를 열지 않는다.
7. 손 뻗기는 `기타` 시도와 같은 장벽 상태를 만든다.
8. 세션 초기화는 베스트/미선택/경고 닫힘 상태로 돌아간다.
9. 화면 보정 회전은 로컬 Z축 π 라디안이고 화면 법선을 유지한다.
10. 기존 standalone 회귀 테스트, DialogueKit 테스트, generic visionOS Simulator 빌드를 통과한다.

### 8.2 수동 검증

Simulator와 Vision Pro에서 다음을 확인한다.

1. 로고와 메뉴 글자가 정방향이며 화면 상단이 실제 키오스크 상단에 위치한다.
2. UI가 Screen 면을 벗어나거나 뒤집히지 않고 z-fighting이 없다.
3. 일반 카테고리 탭이 각각 정상 전환된다.
4. `기타`를 선택해도 탭이 선택되지 않고 중앙 경고가 즉시 보인다.
5. 경고를 닫으면 Mission 2에서 다시 시도할 수 있다.
6. `직원에게 직접 주문하기`를 선택하면 Mission 3가 갱신되고 직원 NPC 흐름이 이어진다.
7. 손을 높은 탭 쪽으로 뻗어도 같은 경고가 한 번만 나타난다.
8. 앉은 시야에서 경고 문구와 두 버튼을 읽고 선택할 수 있다.

## 9. 완료 기준

- 실제 키오스크에서 UI가 정방향으로 보인다.
- 첨부 레퍼런스와 같은 노랑·검정 고대비 정보 구조를 갖는다.
- 일반 카테고리는 전환되며 `기타`만 의도적으로 실패한다.
- 레인보우 스무디를 찾으려다 접근성 장벽을 경험하고 직원 주문 미션으로 자연스럽게 이어진다.
- develop에서 들어온 기존 기능과 현재 브랜치의 다른 기능을 제거하거나 우회하지 않는다.
- 자동 검증과 Simulator 빌드가 통과한다.
- 최종 수용 여부는 사용자 직접 공간 검증 후 결정한다.

## 10. 제외 범위

- 실제 장바구니, 결제, 주문 완료
- 외부 메뉴 API
- 첨부 이미지의 개별 상품 사진 복제
- 키오스크 3D 모델 또는 `Indoor.usda` 편집
- NPC 대화 내용과 애니메이션 변경

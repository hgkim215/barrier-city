# Outdoor 맵 로딩 복구 설계

## 목표

visionOS 몰입 공간 진입 시 현재 RealityKitContent 번들에 포함된 `Outdoor` 장면을 보이는 월드와 충돌 월드에 모두 로드한다. 장면 로딩이 다시 실패하면 조용히 빈 공간으로 진행하지 않고 원인을 진단할 수 있는 오류를 남긴다.

## 원인

`ImmersiveView`는 보이는 장면과 충돌 장면을 각각 `Entity(named: "Map")`으로 요청한다. 그러나 `Map.usda`는 에셋 정리 커밋에서 삭제됐고 현재 번들에는 `Outdoor.usda`와 `Outdoor.usdz`가 있다. 두 요청 모두 `try?`를 사용해 실패를 `nil`로 바꾸므로 앱은 종료되지 않지만 카페 맵 없이 몰입 공간을 구성한다.

## 접근 방식

1. **권장: 정식 `Outdoor` 에셋을 명시하고 오류를 기록한다.** 현재 에셋 구성을 단일 진실 원천으로 사용하고 잘못된 이름을 즉시 드러낸다.
2. **`Map`을 찾은 뒤 `Outdoor`로 폴백한다.** 과거 번들과 호환되지만 삭제된 이름을 계속 정상 경로로 인정해 결함을 숨긴다.
3. **삭제된 `Map.usda`를 복원한다.** 코드 변경은 작지만 현재 `Outdoor`/`Indoor` 장면 구조와 중복되는 구형 에셋을 되살린다.

첫 번째 방식을 사용한다.

## 설계

- `ImmersiveView` 내부에 야외 시작 장면 이름을 나타내는 단일 상수 `outdoorSceneName`을 둔다.
- 보이는 맵과 충돌 맵은 모두 이 상수로 `Outdoor`를 로드한다. 기존 물리 제거, 렌더링 제거, 충돌 생성 및 `InteractionModel` 참조 연결 순서는 유지한다.
- 각 로드 작업은 `do/catch`로 감싸고 `Logger`에 장면 이름과 실패 위치를 남긴다. 보이는 맵 실패와 충돌 맵 실패를 구분해 한쪽만 실패해도 진단할 수 있게 한다.
- 부분 실패 시 현재의 디버그 바닥, 휠체어와 조명 구성은 계속 진행한다. 이 수정에서 몰입 공간 자체를 강제 종료하거나 별도 오류 UI를 추가하지 않는다.

## 회귀 검증

- 독립 실행 가능한 소스 계약 테스트를 먼저 추가한다.
- 테스트는 `ImmersiveView`가 `Outdoor`을 단일 상수로 선언하고 두 로드 경로에서 재사용하는지 확인한다.
- 테스트는 `Map` 직접 참조와 장면 로드의 `try?` 사용을 금지하고, 현재 에셋 디렉터리에 `Outdoor.usda`가 실제 존재하는지 확인한다.
- RED 단계에서는 기존 `Map` 참조 때문에 실패해야 한다. 구현 후 같은 테스트와 기존 회귀 테스트를 실행한 뒤 visionOS Simulator 대상으로 전체 앱을 빌드한다.

## 범위 밖

- 야외 맵의 좌표, 크기, 조명, 충돌 생성 알고리즘은 변경하지 않는다.
- `Indoor` 전환과 키오스크 Screen UI 동작은 변경하지 않는다.
- 기존의 스테이징되지 않은 Xcode 프로젝트 설정 변경은 보존하고 이번 커밋에 포함하지 않는다.
